## v0.1.2 四项改动（用户提 bug + 给补丁 + 提需求）
1. **天气详情弹窗 7 日预报被裁切**（bug）：根因是 `.modal` 默认 `min(420px,92vw)`，减内边距后 380px ÷ 7 列 = 每列 47px，而温度行「26°18°」需约 56px，被 `overflow:hidden` 裁掉。改法：删除 `#wxDDays` 内联 `repeat(7,1fr)`，`.wx-days` 改 `repeat(auto-fit,minmax(76px,1fr))`，`#wxDetailMask .modal` 加宽到 `min(680px,94vw)` 且正文超高内部滚动。
2. **Docker 监控采集并行化**：应用用户给的 `monitor_perf_fix.diff`（ThreadPoolExecutor 16 并发）。实测（假 docker client，单容器 stats 阻塞 1s，18 运行/21 总）：18s → 2.01s。额外加了单飞锁 `threading.Lock()` + 2s TTL 缓存，防止采集耗时超过 5s 轮询间隔时线程池堆积。**计算口径逐行比对与用户版一致**（仅 `cache` 局部变量改名 `page_cache`）。
3. **新增容器内存占比饼图**：monitor.js 新增 `renderCtPie()`，纯 SVG 圆环（`stroke-dasharray`/`dashoffset`），前 8 个容器独立扇区 +「其他 N 个容器」合并，悬浮圆心显示明细。index.html 中「容器曲线」卡由 col-12 改 col-8，饼图卡 col-4 同行。
4. **仪表盘组件拖拽调大小**：编辑态右下角注入 `.dash-resize` 手柄，横向按列吸附（3~12）、纵向 20px 吸附；用 CSS 变量 `--dash-col`/`--dash-h` + `.sized` 类而非内联 grid-column，**窄屏（<1281px）移除 `.sized` 回落 col-* 响应式规则**；双击手柄恢复默认。后端 `DashboardIn` 增 `sizes` 字段 + `_clean_sizes()` 白名单校验（col 3~12、h 160~2000、组件 id 必须在 DEFAULT_WIDGETS）。
- 版本同步：app_version.py → 0.1.2，CHANGELOG 置顶 5 条。

## 浏览器实测发现的两个隐藏 bug（v0.1.2 补刀）
- **管理员登录后看不到系统监控入口**（v0.1.0 起就有）：`monitorEnabled` 只在 `/api/auth/session` 路径注入，登录/注册/切换三条路径都没带，必须刷新才出现。修法：把它下放到 `_public_user()` 统一下发；删掉 app.js 里那行 `s.user.monitorEnabled = !!s.monitorEnabled` 的临时补丁。
- **饼图悬浮高亮每 5 秒被轮询重绘清空**：`renderCtPie()` 每次重建 legend/segs 节点会清空 `.hot`/`.dim`。修法：用 `ctPieHover` 记住当前悬浮索引，重绘后 `pieHover(ctPieHover)` 恢复。

## 浏览器自动化（环境要点）
- 装 `agent-browser` 时 Chromium 从 storage.googleapis.com 下载会卡在 9/179MB 超时（沙箱/网络限制）。**绕过办法**：直接启动本机 Chrome 的调试端口（`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome --headless=new --no-sandbox --disable-dev-shm-usage --remote-debugging-port=9222 --user-data-dir=/tmp/xxx-profile --disable-gpu`），然后 `agent-browser connect 9222`。`--no-sandbox` 必须（外层沙箱里 Chrome 自家沙箱起不来）。
- agent-browser 的 `network route --body` 对 fetch 请求好像没生效（实测没拦截到），更靠谱的是**覆写 `window.fetch`**：用 `Response` 构造假响应，等下一次 5 秒轮询自然命中。可结合 `setInterval` 验证悬浮高亮能否跨轮询保持。
- **真正用沙箱代理（HTTP_PROXY=127.0.0.1:64690）** 可以通到本地服务（curl 返回 200），之前以为不行——只要服务真的监听 0.0.0.0:8000 就行。HTTP 端到端测试走 `urllib.request` 即可，**不需要再 import 模块 + 假对象了**。
- **后台进程必须在 `run_in_background: true` 启动**才会持续到下次工具调用。`nohup ... &` 在同一次 Bash 调用内有效，但该调用结束后沙箱会回收子进程。
