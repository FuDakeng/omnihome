## v0.2.5：网络真实速率 + 多物理硬盘 + 知识库重构 + 关于卡重排版

### Bug 1：网络指标数据不对
- **双层根因**：① 后端返回的是开机累计字节（`net.bytes_recv / 1048576`），单位标 `Mbps` 错误；② 前端 `#monNetSub` 用 `s.netUpMbps`（上传值）但标签写"累计下载"。
- **修法**：
  - 新增 `_NET_PREV` 按方向分别保存（关键：之前一个请求里 `up` 与 `down` 共用 prev_ts/prev_val，第二次调用 dt 微秒级 + diff=累计字节 → 算出 22 TB/s 的伪速率。**每个方向独立 init** 才能避开）。
  - 首次调用 dt<0.5s 或 prev_ts=0 都返回 0，避免前端渲染假速率。
  - 前端副标签改成 `↑ X MB/s · 当前上传速率`，与数据对齐。

### Bug 2：硬盘只显示根分区
- 根因：`psutil.disk_usage("/")` 永远只看根，4 块盘的 NAS 只剩 1 块。
- 修法：枚举 `/sys/block/*`，过滤回环/ram/dm-* 与分区（用 `/partition` 文件判定），再用 `psutil.disk_partitions` 把分区按"父磁盘"归类（处理 `sda1→sda`、`nvme0n1p1→nvme0n1`、`mmcblk0p1→mmcblk0` 三种命名规则）。
- **坑**：`psutil` 在 routes.py 里是**惰性导入**（在 endpoint 内部 `import psutil`），所以新加的辅助函数要用 psutil 时也得自己 `import psutil as _psu`，否则 `NameError: name 'psutil' is not defined`。
- **坑**：`sdiskusage`（`disk_usage` 返回值）在 macOS/Linux 都没有 `.mountpoint` 属性，兜底分支不能 `root_disk.mountpoint`，直接用 `"/"`。

## v0.2.7：修复「升级后前端不刷新」（静态资源缓存策略）

### 现象
用户反馈：装了新包后强制刷新，**只有更新日志变了，界面和上个版本一模一样**，怀疑打包出错。

### 排查（先别急着改代码，先证伪）
- 包内 `?v=0.2.6`、VERSION、新按钮（6 处）、新 CSS（25 处）、新 JS（11 处）、disk 过滤、import-md 全部在 → **包没问题**。
- 服务端实际吐出的 HTML 含全部新元素，JS/CSS 内容也是新的 → **服务也没问题**。
- compose 只挂 `./data:/app/data`，`backend/`、`demo/` 靠 COPY 进镜像；`.dockerignore` 没排除 demo → **部署配置也没问题**。

### 真因
`main.py` 里 `FileResponse` **没设任何 Cache-Control**，浏览器/反向代理可随意缓存 `index.html`。
旧 HTML 继续引用 `?v=0.2.5` 的旧 JS/CSS → 界面不变；
而更新日志是浏览器**动态请求** `/api/about` 拿的 → 新后端返回新日志。
**"只有日志变、界面不变"就是这个组合的典型症状。**
NAS 上若套了反向代理（Nginx Proxy Manager / Cloudflare Tunnel），很可能按路径缓存、忽略 query 参数，那样 `?v=` 换新也救不了。

### 修法
- `index.html`（文档本身）→ `Cache-Control: no-cache, must-revalidate`，每次校验，保证升级后一定拿到新文档。
- 带 `?v=x.y.z` 版本戳的 js/css → `public, max-age=31536000`（一年）长缓存。因为文档是 no-cache，发版换戳就是新 URL，长缓存不会挡住更新。

### 验证
- 解包目录启动（与容器 CMD `python backend/main.py` 一致）：
  `/` → no-cache；`/js/*`、`/css/*` → 一年长缓存；`/api/about` → v0.2.7，日志最新 0.2.7。
- index.html 含 notesImportBtn / edCrumb / assetLightbox / kbSideToggle，`?v=0.2.7`。

### 经验
以后遇到「升级后界面没变」：先用 `curl -s http://host:8000/ | grep -o '新元素id'` 判断是**服务端旧**还是**缓存旧**，再决定改代码还是清缓存。不要一上来就怀疑打包。
