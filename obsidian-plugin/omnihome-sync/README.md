# OmniHome Sync · 万事屋 ↔ Obsidian 双向同步插件

把你自托管的 **「万事屋」门户知识库** 与 Obsidian 仓库双向同步。数据全程存于你自己的服务器（PostgreSQL / SQLite / 文件），不经任何第三方云。支持桌面端与移动端。

- **纯 JavaScript 实现**（CommonJS，`require('obsidian')`），无需 Node 构建，仓库内即是可直接侧载的成品。
- **按笔记仓库同步**：路径 = `文件夹/标题.md`，LWW 冲突策略，删除安全阀。门户可下载插件 zip。

---

## 一、安装（BRAT 侧载，推荐）

本插件尚未上架 Obsidian 官方市场，用 [BRAT](https://github.com/TfTHacker/obsidian42-brat) 侧载最省事。

### 方式 A：BRAT + Git 仓库（推荐，可自动更新）

1. Obsidian → 设置 → 第三方插件 → 浏览社区插件 → 搜索并安装 **Obsidian42 - BRAT**，启用它。
2. 打开 BRAT 设置 → **Add Beta plugin**。
3. 填入本仓库地址：`https://git.jeanlaw.xyz/jeanlaw/omnihome`
   - 若仓库需要鉴权，BRAT 支持填写用户名 + Access Token。
4. BRAT 会拉取仓库并识别 `obsidian-plugin/omnihome-sync/` 下的 `manifest.json`。
   > 若 BRAT 未在根目录识别到插件，请把 `obsidian-plugin/omnihome-sync` 单独作为一个仓库/子模块提供，或用下面的方式 B 手动放置。
5. 启用插件，进入其设置页配置。

### 方式 B：手动放置目录（最简单，离线可用）

把本目录 `obsidian-plugin/omnihome-sync/` 整个复制到你的仓库插件目录：

```
<vault>/.obsidian/plugins/omnihome-sync/
├── manifest.json
├── main.js
├── styles.css
└── README.md
```

然后 Obsidian → 设置 → 第三方插件 → 关闭「安全模式」→ 刷新已安装插件列表 → 启用 **OmniHome Sync（万事屋同步）**。

## 二、配置

1. 在门户站点登录后，进入 **设置 → 功能设置 → Obsidian 插件同步**，打开开关：
   - 记下「服务端地址」（即门户根地址，形如 `https://home.example.com`）。
   - 为要同步的笔记仓库点击 **生成令牌**，明文（`ohs_…` 开头）**只显示一次**。可用 **一键复制连接信息**（含服务端地址与 API Key）。系统内置仓库不可同步。
2. 回到 Obsidian，打开本插件设置页：
   - **一键粘贴连接信息**：把上一步复制的 `OMNIHOME_SYNC` 文本贴入即可自动填写地址与 Key。
   - 或手动填写 **服务端地址**（含协议与端口、**无末尾斜杠**）和 **API Key**。
   - **轮询间隔**：默认 8 秒（3–300 秒）。
3. 点击 **测试连接**，提示连接成功即配置正确。
4. 打开 **启用同步** 开关。首次会自动做一次全量对账。

> 左侧功能区图标按连接成功 / 失败显示不同状态。点击可暂停同步、立即同步、打开万事屋、查看信息、打开插件设置；高危菜单可将本地仓库与服务端互相覆盖（需确认）。设置页支持一键粘贴万事屋「连接信息」。底部有同步日志。

## 三、同步规则

### 3.1 路径与范围
- 门户的 **文件夹层级** 对应 vault 的 **目录结构**，一篇 **笔记** 对应一个 **`.md` 文件**，路径为 `文件夹/标题.md`。
- **只同步普通笔记**。常驻笔记（如生词本等 pinned）、内置文件夹「每日计划」「灵感速记」由服务端过滤，**不会**进入 vault，也不会被上传。
- 隐藏文件 / 目录（任一段以 `.` 开头，如 `.obsidian`、`.git`、`.trash`）与系统垃圾（`._*`、`__MACOSX` 等）一律跳过。

### 3.2 冲突处理（LWW：最后修改时间优先）
- 两端都有同一文件且都改动时，**mtime 较新者胜**。
- **2 秒同刻窗口内站点优先**：当客户端时间与服务端时间相差不足 2 秒，以服务端版本为准，客户端回拉，避免时钟抖动造成误覆盖。
- **服务端无独立变更不回拉**：连续在 Obsidian 里输入时，插件会带上「上次同步的站点 mtime」。若服务端并未被其它端改过，即使落在 2 秒窗口内也会落地本地内容，**不会**回拉旧正文，也就不会触发 Obsidian「文件已被外部修改，正在自动合并更改」。
- 站点拒绝本地推送时（`applied:false` **且** 站点 mtime 确实更新），插件会自动回拉站点较新版本，本地让位。

### 3.3 附件
- 笔记里引用的本地图片 / 文件（png、jpg、gif、webp、svg、pdf、mp3、mp4、webm、wav、zip，单文件不超过 5MB）会随笔记一并同步到门户「附件」分区。
- 推送到门户时，引用改写为 `/api/notes/assets/…`，门户预览可直接显示；拉回 Obsidian 时下载到仓库（已有原文件则保持原路径，否则落到 `OmniHome-assets/`）并还原为 `![[路径]]` wiki 链接。

### 3.4 删除安全阀
- 单轮对账中，**两个方向计划删除合计超过 10 个**文件时，插件**暂停**并弹出确认框。
- 「继续删除」执行删除；「取消」会**暂停同步**，在你手动「恢复同步」之前不再弹出大量删除确认。
- 删除是**可恢复**的：本地删除移入 vault 的 `.trash`；服务端删除进入门户「回收站」（软删），可在门户恢复。

### 3.5 重命名
- 在 vault 内重命名 / 移动已同步过的笔记，插件走服务端 **rename** 接口，**保持笔记身份与历史**（不会退化成「删除 + 新建」而丢失笔记 ID）。

### 3.6 高危覆盖
- 侧栏菜单与设置页提供 **用当前仓库覆盖服务端** / **用服务端覆盖当前仓库**，需确认。会按选定方向对齐全部笔记（多出的一端进回收站或本地 `.trash`），绕过 LWW 与删除安全阀。

### 3.7 通知
- 变更按 **30 秒聚合**通知（「N 处变更已同步」），不频繁打扰。
- 错误通知按 **60 秒节流**，轮询失败不会刷屏。

### 3.8 状态栏
状态栏显示同步态：`↻ 同步中…` / `✓ 已同步` / `⊘ 未启用` / `⏸ 已暂停` / `⚠ 错误`（悬停查看详情）。

## 四、移动端与公网访问

- 本插件 `isDesktopOnly: false`，**支持移动端**（iOS / Android）。
- 移动端在外网访问 NAS 上的门户时，需要门户可从公网到达：
  - 用 **DDNS / 内网穿透**（frp、Cloudflare Tunnel、Tailscale Funnel 等）暴露服务；
  - **强烈建议启用 HTTPS**（反向代理签发证书），否则 API Key 明文传输有泄露风险；
  - 服务端地址填公网域名，如 `https://home.example.com`。
- 插件通过 Obsidian 的 `requestUrl` 发起请求，**绕过浏览器 CORS**，移动端与跨域均可用。

## 五、常见问题

**Q：测试连接报 401 / API Key 无效？**
A：API Key 在门户「重置」或「吊销」后旧 Key 立即失效，请重新生成并粘贴。明文只在生成时显示一次。

**Q：门户里有些笔记在 vault 里看不到？**
A：常驻笔记（pinned，如生词本）与「每日计划」「灵感速记」文件夹内的笔记不在同步范围，这是有意为之，避免系统功能笔记污染 vault。

**Q：本地删了文件，服务端会不会真删？**
A：不会物理删除。服务端走软删进「回收站」，可在门户恢复；本地移入 vault 的 `.trash`。且单轮删除超 10 个会先弹确认。

**Q：换设备 / 重装插件后基线丢失会怎样？**
A：基线（`path -> mtime` 映射）存于插件本地配置。丢失后首轮对账会按 LWW 重新比较两端 mtime，正常情况下不会误删；若两端都无基线且路径都存在的文件，按内容 mtime 决胜。

**Q：多台设备同时改同一篇会怎样？**
A：以 mtime 较新者为准（LWW），2 秒内站点优先。跨设备时钟偏差是已知局限，建议各设备开启自动校时。

**Q：同步会不会把 `.obsidian` 配置也传上去？**
A：不会。任何以 `.` 开头的段（`.obsidian` / `.git` / `.trash` 等）都被跳过。
