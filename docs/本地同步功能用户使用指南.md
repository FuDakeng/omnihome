# 本地同步功能用户使用指南

> 适用版本：0.2.20 起 · 适用浏览器：Chrome / Edge（桌面版）

## 这是什么

把电脑上的一个普通文件夹授权给万事屋知识库后，文件夹里的 Markdown 文件与站内笔记**双向实时同步**：

- 在 VS Code / Obsidian / Typora 等本地编辑器改文件 → 网站自动更新；
- 在网站上编辑、新建、重命名、删除笔记 → 本地文件实时写入；
- 文件夹里的子目录对应知识库的文件夹层级（`工作/项目A.md` → 文件夹「工作」下的笔记「项目A」）。

## 如何授权绑定

1. 进入**知识库**视图，点目录顶端 **⋯ 更多操作** → **本地文件夹同步**；
2. 点「选择本地笔记文件夹」，在浏览器弹出的原生选择器中挑选（或新建）一个专用文件夹，允许**读写**权限；
3. 绑定后立即执行首次全量对账：本地已有的 `.md` 会导入站点，站点已有而本地没有的笔记会写入本地——两边内容合并，不会互相清空。

> 建议为同步单独建一个文件夹（如 `Documents/OmniHome笔记`），不要直接授权整个「文稿」或磁盘根目录。

## 日常使用

- **无需任何操作**。绑定后网站每 5 秒感知一次本地变化（仅页面可见时），站点侧的每次保存也会实时落盘；
- 刷新页面、关闭浏览器再打开：**不需要重新选择文件夹**，授权自动恢复；若浏览器要求确认，面板中会出现「恢复授权」按钮，点一下即可；
- 断网或关页期间在本地做的修改，重新打开网站后**自动补齐同步**；
- 面板中可随时「暂停同步」「立即同步」「解绑」（解绑只断开同步关系，两边文件都保留）。

## 冲突如何处理

采用**最后修改时间优先（LWW）**策略：

| 场景 | 结果 |
| --- | --- |
| 只有本地改了 | 本地内容推送到网站 |
| 只有网站改了 | 网站内容回写本地文件 |
| 两边都改了 | 修改时间较新的一方胜出，另一方被覆盖 |

因此**不建议同一篇笔记在两边同时开着改**。若担心覆盖，可在面板「暂停同步」后再做大批量本地整理。

## 删除的语义（重要）

- 删除**本地文件** → 站点对应笔记同步删除；
- 删除**站点笔记** → 本地对应文件同步删除；
- 安全阀：单轮对账发现超过 **10 个**本地文件同时消失（如误删整个目录、同步盘回滚），会**暂停删除同步**并在日志中提示，需人工确认后处理。

## 浏览器兼容与降级

- **Chrome / Edge**：完整双向实时同步；
- **Safari / Firefox**：不支持 FileSystem Access API，同步面板会显示说明，功能入口不报错；请继续使用知识库 ⋯ 菜单的「导入 Markdown / zip」「导出全部笔记」手动搬运，基础笔记功能不受影响。

## 常见问题

- **提示「文件夹访问权限已被撤销」**：在系统/浏览器设置中清除了站点权限，或文件夹被移动。打开同步面板点「恢复授权」；仍失败就解绑后重新选择文件夹；
- **文件格式**：站内写出的文件与「导出为 .md」一致（首行 `# 标题` + 正文）；本地文件若首行是 `# 标题`，导入时会作为笔记标题；
- **隐藏文件**：以 `.` 开头的文件与文件夹（如 `.git`、`.obsidian`）不参与同步；
- **同名笔记**：同目录下标题相同的两篇笔记，第二篇文件名会自动追加 `-2`、`-3` 序号，避免互相覆盖。
