# Obsidian 同步插件 · 用户使用指南

> 适用版本：0.2.27 起 · 客户端：Obsidian 桌面版 / 移动版 · 插件：OmniHome Sync（万事屋同步）

## 这是什么

把你自托管的 **万事屋门户知识库** 与 **Obsidian 仓库** 双向同步：

- 在 Obsidian 里改笔记 → 门户站点自动更新；
- 在门户里编辑、新建、重命名、删除笔记 → Obsidian 仓库自动同步；
- 门户的 **文件夹层级** 对应 vault 的 **目录结构**（`工作/项目A.md` → 文件夹「工作」下的笔记「项目A」）；
- **数据全程存于你自己的服务器**（NAS 上的 PostgreSQL / SQLite / 文件），不经任何第三方云。

它按**笔记仓库**签发令牌：每个 Obsidian 库绑定万事屋的一个仓库（默认仓库或你自建的仓库）。系统内置仓库（每日计划 / 灵感速记 / 常驻）不同步。

---

## 一、准备工作

### 1. 在门户生成 API Key

1. 登录门户站点，进入 **设置 → 功能设置 → Obsidian 插件同步**，打开开关；
2. 记下「服务端地址」（门户根地址，形如 `https://home.example.com` 或 `http://192.168.1.100:8000`）；
3. 为要同步的**笔记仓库**点 **生成令牌**（默认仓库、自建仓库各一枚；系统内置仓库不可同步），明文（`ohs_` 开头）**只显示一次**，立即点「复制」保存好。

> ⚠️ 令牌相当于该仓库的同步专用密码。**重置**或**吊销**后旧令牌立即失效，Obsidian 端需重新填写。一个 Obsidian 库对应一个笔记仓库令牌。

### 2. 安装插件

插件尚未上架 Obsidian 官方市场，用 **BRAT** 侧载或手动放置目录。详见插件目录内 `obsidian-plugin/omnihome-sync/README.md`「一、安装」。简述：

- **方式 A（BRAT，推荐）**：安装社区插件 **Obsidian42 - BRAT** → Add Beta plugin → 填仓库地址 `https://git.jeanlaw.xyz/jeanlaw/omnihome`。
- **方式 B（手动）**：把 `obsidian-plugin/omnihome-sync/` 整个目录复制到 `<vault>/.obsidian/plugins/omnihome-sync/`，然后在「第三方插件」里关闭安全模式、启用它。

## 二、配置插件

打开 Obsidian → 设置 → **OmniHome Sync · 万事屋同步**，填写：

| 项 | 说明 |
| --- | --- |
| **服务端地址** | 门户根地址，含协议与端口、**无末尾斜杠**。移动端 / 公网请用域名 + HTTPS |
| **API Key** | 粘贴门户生成的明文（`ohs_…`） |
| **轮询间隔（秒）** | 定期检查服务端变更，建议 5–10 秒（可填 3–300） |

填好后点 **测试连接**，提示「连接成功，服务端有 N 篇可同步笔记」即配置正确。然后打开 **启用同步** 开关。

> - 左侧功能区图标按连接成功 / 失败显示不同状态。点击可：**暂停同步**、**立即同步**、**打开万事屋**、**查看信息**（插件版本、万事屋版本、地址、仓库）。
> - 命令面板（Ctrl/Cmd+P）有「OmniHome Sync：立即同步」「暂停 / 恢复同步」两条命令。
> - 插件设置页底部可查看同步日志；门户「功能设置」里也有同一份服务端日志。
> - 状态栏显示同步态：`↻ 同步中…` / `✓ 已同步` / `⊘ 未启用` / `⏸ 已暂停` / `⚠ 错误`（悬停看详情）。

## 三、日常使用

- **无需任何操作**。启用后插件会：
  - 首次自动做一次**全量对账**（两端已有的笔记按规则合并，不会互相清空）；
  - 监听 vault 的**新建 / 修改 / 删除 / 重命名**，防抖 800ms 后增量同步；
  - 每隔「轮询间隔」拉一次服务端 `/list`，把门户侧的变更同步到 vault。
- 变更按 **30 秒聚合**弹通知（「N 处变更已同步」），不频繁打扰；错误通知按 60 秒节流，不刷屏。
- 断网 / 关闭 Obsidian 期间在门户做的修改，重新打开后自动补齐。
- 设置页里可随时 **立即同步** / 关闭「启用同步」**暂停** / **解绑**（清空配置与同步基线，**不删除**任何本地文件或服务端笔记）。

## 四、同步规则

### 4.1 同步范围
- **只同步普通笔记**。常驻笔记（`pinned`，如生词本）、内置文件夹「每日计划」「灵感速记」下的笔记**不在范围内**，由服务端过滤，不会进入 vault，也不会被上传。
- 笔记内**引用的附件**（图片、pdf、音视频、zip 等，单文件 ≤5MB）会随笔记一起同步；门户预览走 `/api/notes/assets/…`，Obsidian 侧保持 wiki 链接。
- 隐藏文件 / 目录（任一段以 `.` 开头，如 `.obsidian`、`.git`、`.trash`）与系统垃圾（`._*`、`__MACOSX`）一律跳过。

### 4.2 冲突处理（LWW：最后修改时间优先）
| 场景 | 结果 |
| --- | --- |
| 只有本地改了 | 本地内容推送到门户 |
| 只有门户改了 | 门户内容回写本地 |
| 两边都改了 | 修改时间较新的一方胜出 |
| 两边修改时间相差不足 2 秒 | **门户（站点）优先**，本地让位回拉 |
| 服务端自上次同步后并无变更 | **不回拉**，连续本地输入直接落地（避免误报「文件已被外部修改」） |

「2 秒内站点优先」是为了对抗跨设备时钟抖动，避免误覆盖。因此**不建议同一篇笔记在两端同时开着改**；多设备请开启自动校时。

### 4.3 删除的语义（重要）
- 删除 **vault 里的文件** → 门户对应笔记同步删除；
- 删除 **门户里的笔记** → vault 对应文件同步删除；
- 删除都是**可恢复**的：本地移入 vault 的 `.trash`；门户走**软删进「回收站」**，可在门户恢复。
- **删除安全阀**：单轮对账中两个方向计划删除**合计超过 10 个**文件时，插件**暂停**并弹确认框——「继续删除」执行，「取消」跳过本轮删除（其余变更照常应用），请人工核对后再手动同步。这能防止误删整个目录或首次绑定错位造成的大面积删除。

### 4.4 重命名 / 移动
- 在 vault 内重命名或移动一篇**已同步过**的笔记，插件走服务端 **rename** 接口，**保持笔记 ID 与历史**（不退化成「删+建」）。

### 4.5 同名笔记
- 同一文件夹下标题相同的两篇笔记，第二篇文件名自动追加 `-2`、`-3` 序号，避免互相覆盖（与浏览器版规则一致）。

## 五、移动端与公网访问

插件支持移动端（iOS / Android，`isDesktopOnly:false`）。手机在外网访问 NAS 上的门户时：

1. 让门户可从公网到达：**DDNS / 内网穿透**（frp、Cloudflare Tunnel、Tailscale Funnel 等）；
2. **强烈建议启用 HTTPS**（反向代理签发证书）——否则 API Key 明文传输有泄露风险；
3. 插件「服务端地址」填公网域名，如 `https://home.example.com`。

插件通过 Obsidian 的 `requestUrl` 发请求，**绕过浏览器 CORS**，移动端与跨域都能用。

## 六、常见问题

- **测试连接报 401 / API Key 无效**：Key 在门户被「重置」或「吊销」后旧 Key 立即失效，请重新生成并粘贴。明文只在生成时显示一次。
- **门户里有些笔记在 vault 看不到**：常驻笔记（生词本等 pinned）与「每日计划」「灵感速记」不在同步范围，这是有意为之，避免系统功能笔记污染 vault。
- **本地删了文件，门户会真删吗**：不会物理删除，走软删进「回收站」，可在门户恢复；且单轮删除超 10 个会先弹确认。
- **换设备 / 重装插件后**：同步基线存于插件本地配置，丢失后首轮对账会按 LWW 重新比较两端 mtime，正常不会误删；若两端都无基线且都存在同路径文件，按内容 mtime 决胜。
- **`.obsidian` 配置会被传上去吗**：不会，任何以 `.` 开头的段都被跳过。
- **文件格式**：站内写出的 `.md` 首行是 `# 标题`（与门户「导出为 .md」一致）；本地 `.md` 若首行是 `# 标题`，导入时会作为笔记标题。
- **暂停 / 解绑会不会删笔记**：都不会。暂停只停止同步；解绑只清空插件配置与基线，本地文件与门户笔记都保留。
